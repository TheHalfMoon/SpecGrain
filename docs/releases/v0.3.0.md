# SpecGrain v0.3.0

**Big ideas. Small specs. Proven software.**

v0.3.0 is a backward-compatible recursive authoring release. It packages the already-verified native root/child DRAFT authoring and explicit recovery surfaces delivered before Specification 020 without expanding lifecycle, readiness, or execution authority.

## Added since v0.2.0

- public `create_child_draft_spec` API for creating one child SpecNode fixed to `DRAFT` under an existing parent that also remains `DRAFT`;
- `specgrain draft --parent SG-XXXXXX` for reciprocal child authoring while preserving the existing root-DRAFT path;
- public `recover_authoring_transaction` API and `specgrain recover` CLI for explicit recovery of exact recognized interrupted native-authoring transactions;
- deterministic recovery classifications for no-write, child-only partial write, and completed-write-with-stale-journal states;
- fail-closed refusal when a pending journal or parent/child state is ambiguous.

## Recursive authoring boundary

A child created through the native authoring surface is intentionally `DRAFT`, and its selected parent remains `DRAFT`. Child authoring validates reciprocal refinement structure before publication and uses the ADR-0018 recoverable/fail-closed journal contract instead of claiming operating-system atomicity across two canonical files.

`specgrain recover` is an explicit bounded mutation for an interrupted/pending supported authoring transaction. Ordinary reads do not repair state automatically. Ambiguous transaction state is preserved for manual investigation rather than guessed, overwritten, or destructively cleaned up.

Specification 020 does not change `src/specgrain/` product behavior; it publishes behavior already canonicalized and verified by Specifications 017 and 019.

## Preserved trust boundaries

- No automatic lifecycle promotion, broad `refine`, generic DRAFT editing, readiness synthesis, or execution authority.
- No hosted service, dashboard, account system, telemetry requirement, or runtime model/provider dependency.
- No PyPI or other package-registry publication is claimed by this release.
- Agent adapters remain portable request/result normalization boundaries and do not invoke external agents.
- Spec Kit import remains read-only and does not mutate source repositories or silently promote legacy tasks.
- SpecGrainBench still has no published controlled multi-arm empirical dataset; no benchmark winner is claimed.
- Runtime third-party dependency count remains zero.
