# Support

SpecGrain is developed in public. Support requests should stay reproducible, bounded, and free of secrets or sensitive data.

## Supported surfaces

Two surfaces may differ intentionally:

- **Published release:** `v0.3.0`, the stable historical GitHub Release documented in `README.md` and `CHANGELOG.md`.
- **Current `main`:** unreleased source that may contain additional canonical capabilities. Current-source behavior does not imply a newer published release.

When asking for help, state which surface you are using and include the exact release tag or commit SHA.

## Before opening an issue

1. Read the relevant README and project documentation.
2. Search existing issues for the same behavior.
3. Reduce the problem to the smallest reproducible example.
4. Record the exact SpecGrain version/commit, Python version, operating system, command/API surface, and observed output.
5. Remove credentials, private repository content, personal data, and other sensitive material.

## Where to ask

- **Reproducible defect:** use the Bug report issue template.
- **Bounded product proposal:** use the Feature request issue template. A request is not automatically roadmap authority; product work remains evidence-shaped under repository governance.
- **Security vulnerability:** follow `SECURITY.md`. Do not publish exploit details in a normal issue.
- **Contribution/process question:** read `CONTRIBUTING.md` and `AGENTS.md` before opening an issue.

## What support does not imply

Maintainer discussion, issue labels, feature requests, donor references, or implementation suggestions do not by themselves authorize a new product specification, release, benchmark claim, or execution/provider integration.

Repository governance and live canonical evidence remain authoritative.
